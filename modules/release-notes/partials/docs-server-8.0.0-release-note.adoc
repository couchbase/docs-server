[#release-80]
== Release 8.0 (August 2025)

Couchbase Server 8.0 was released in August 2025.
This maintenance release contains fixes to issues.

== Fixed Issues






=== Storage

[#dlist-known-issues-80-storage]


*https://jira.issues.couchbase.com/browse/MB-60542/[MB-60542]*::

The Couchbase Server and Couchbase Columnar builds incorporate the kv_engine commit [fd8914a](https://github.com/couchbase/kv_engine/commit/fd8914a76eedf8a3bc515c550581359a93efb0f6) with the commit message referencing MB-60542. This update involves parsing and dumping the "deprecated" and "notes" fields in the `gen_stat_definitions.cc` file. Both Couchbase Server 8.0.0-1545 and Couchbase Columnar 1.2.0-1009 include this change.

*https://jira.issues.couchbase.com/browse/MB-61385/[MB-61385]*::

Couchbase made changes to handle invalid CAS values, implementing a new "MaxFutureCasThreshold" to guard against CAS inconsistencies that could disrupt XDCR replication. They introduced two configurable modes for handling these values: "error," which rejects operations, and "replace," which regenerates the CAS. To address compatibility and potential CAS issues, three approaches were identified: a fix to reject faulty CAS inputs (MB-61385), a fix to prevent sending documents with invalid CAS (MB-55758), and support for extended error handling (MB-62034). The implementation details and strategies were refined to allow dynamic configuration and ensure compatibility across different versions. Furthermore, changes to default configurations were tracked via new configuration parameters and upcoming API adjustments.

*https://jira.issues.couchbase.com/browse/MB-65644/[MB-65644]*::

Couchbase-server-8.0.0-2772 includes an indexing commit that addresses issue MB-65644. The change involves setting the plasma configuration option `enableCompressFullMarshal` to false. This update is associated with commit [c8f3dab](https://github.com/couchbase/indexing/commit/c8f3dab54a4f5fe4f93f98b657ccc03f93d28dd8). The issue will be resolved in version 8.0.0-2905.


=== Data Service

[#dlist-known-issues-80-data-service]


*https://jira.issues.couchbase.com/browse/MB-62295/[MB-62295]*::

The build of couchbase-server version 8.0.0-1668 includes the kv_engine commit [db74893](https://github.com/couchbase/kv_engine/commit/db74893ff4dda84876a821364317b4627437758e), which introduces the use of symbolic links for audit.log as part of resolving MB-62295. This change has been validated on build 8.0.0-2236. The symbolic link points to a timestamped audit log file, which is part of ongoing updates and user transparency efforts in the product. Additionally, the couchbase-columnar-1.2.0-1009 build also incorporates the same kv_engine commit. Release notes need to be updated accordingly with this information.




=== XDCR

[#dlist-known-issues-80-xdcr]


*https://jira.issues.couchbase.com/browse/MB-66140/[MB-66140]*::

In some scenarios, due to race conditions, changing the filter expression or explicit/migration mapping may cause the replication to fail streaming from the beginning. As a consequence, some Source bucket documents may get missed from being replicated to the Target bucket.

+

This has been fixed in 8.0. It is advised to avoid changing these three replication settings:

* filterExpression
* collectionsExplicitMapping
* collectionsMigrationMode

+

until all nodes in the cluster have been upgraded.


=== Query Service

[#dlist-known-issues-80-query-service]


*https://jira.issues.couchbase.com/browse/MB-62793/[MB-62793]*::

The original limit of one XATTR per KV op was relaxed to a maximum of 16 in KV server version 7.6; this ticket explores extending that relaxation to queries.
+
With this change, users can:


. Use up to 15 XATTR fields in their query.


. CREATE INDEX no longer imposes a limit on the number of XATTR fields that can be indexed.

*https://jira.issues.couchbase.com/browse/MB-63459/[MB-63459]*::

New to 7.7.0 is the ability to manipulate document extended attributes (xattrs) via common SQL++ statements.  

+

INSERT and UPSERT statement OPTIONS may now include an “xattrs” object element detailing additions and changes to the xattrs (omissions do not delete xattrs).  The UPDATE statement now supports SET and UNSET of meta().xattrs.{attribute} elements.


=== Eventing Service

[#dlist-known-issues-80-eventing-service]


*https://jira.issues.couchbase.com/browse/MB-64081/[MB-64081]*::

Eventing was not working with App Services due to a Sync Gateway registry parsing issue. The registry object was enclosed in a "config" key within the "_sync" system xattr in cloud deployments, unlike on-prem setups. This caused the Eventing parser to fail. The issue occurs when App Services with Sync Gateway 3.2 co-exist with Eventing version >=7.6.2. Fixes for this issue are under review, targeting a resolution by November 5th. Testing in Capella was not thoroughly conducted before, leading to the current situation. Patches are planned to be backported to earlier versions once approved.

=== Index Service

[#dlist-known-issues-80-index-service]


*https://jira.issues.couchbase.com/browse/MB-64982/[MB-64982]*::

When shard affinity is enabled, the indexer internally maps all replicas of an index to an alternateID. If such an alternateID exists on a node outside the list of nodes, instead of preventing replica creation, the system creates a new replica with the same alternateID on different nodes. This leads to rebalance failures on the affected nodes.
