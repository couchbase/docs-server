




[#release-800]
== Release 8.0.0 (August 2025)

Couchbase Server 8.0.0 was released in August 2025.
This maintenance release contains fixes to issues.

== Fixed Issues






=== Storage

[#dlist-known-issues-800-storage]


*https://jira.issues.couchbase.com/browse/MB-60542/[MB-60542]*::

The builds for Couchbase Server 8.0.0-1545 and Couchbase Columnar 1.2.0-1009 include a kv_engine commit with the identifier fd8914a. This commit addresses MB-60542, focusing on parsing and dumping "deprecated" and "notes" fields.

*https://jira.issues.couchbase.com/browse/MB-61385/[MB-61385]*::

A new feature was added to Couchbase's XDCR to handle CAS (Check-And-Set) value discrepancies. It offers "error" and "replace" modes to handle cases where the CAS value exceeds a predefined threshold, set to 100 seconds ahead of the local clock. The "error" mode rejects the operation, while "replace" regenerates the CAS. A new status code, _cas_value_invalid_, helps track these cases. The XDCR's threshold is set at 1 year, leading to potential replication issues if CAS values are deemed invalid by different thresholds between source and target. The feature's configuration can be adjusted via two new parameters, _hlc_invalid_strategy_ and _dcp_hlc_invalid_strategy_, to manage CAS discrepancies for front-end operations and DCP replication separately.

*https://jira.issues.couchbase.com/browse/MB-65644/[MB-65644]*::

In Couchbase Server 8.0.0-2772, a specific indexing commit (c8f3dab) addresses the issue outlined in MB-65644. The change involves setting the plasma configuration `enableCompressFullMarshal` to false. This update will be finalized and closed in version 8.0.0-2905.


=== Data Service

[#dlist-known-issues-800-data-service]


*https://jira.issues.couchbase.com/browse/MB-62295/[MB-62295]*::

The Couchbase server version 8.0.0-1668 and Couchbase columnar version 1.2.0-1009 both contain kv_engine commit [db74893](https://github.com/couchbase/kv_engine/commit/db74893ff4dda84876a821364317b4627437758e) which implements using a symbolic link for the `audit.log`. This change, aimed at improving audit log handling, was verified in build 8.0.0-2236. The modifications have been recorded under the task [MB-62295](https://jira.issues.couchbase.com/browse/MB-62295). The symbolic link points `current-audit.log` to a specific audit log file. There are mentions of additions needed for the release notes.




=== XDCR

[#dlist-known-issues-800-xdcr]


*https://jira.issues.couchbase.com/browse/MB-66140/[MB-66140]*::

In Couchbase Server build 8.0.0-3074, the commit [2254c2e](https://github.com/couchbase/goxdcr/commit/2254c2e2dff819411869f41233d2179b866f74e2) was introduced. This update includes changes related to XDCR pipelines. Specifically, pipelines undergoing a `PipelineReinitStream` update will not resume from a checkpoint. Instead, a new replication specification setting called 'PipelineReinitHash' has been introduced as part of addressing [MB-66140](https://jira.issues.couchbase.com/browse/MB-66140).


=== Query Service

[#dlist-known-issues-800-query-service]


*https://jira.issues.couchbase.com/browse/MB-51623/[MB-51623]*::

The issue involves an incorrect expiration returned as 0, which should be retrieved through the sub-document API, specifically in JOIN operations, where it only appears on the right side. The query uses a legacy LOOK UP JOIN, lacking subpaths in the plan operator. Corrections are needed for LOOKUP JOIN, LOOKUP NEST, and potentially legacy Index Joins. The system involves using UPSERT and creating an index to perform JOIN operations while managing expiration attributes. The update will be included in Couchbase Server version 7.2.0, addressing these issues and enabling subpaths with legacy joins as per the commit. Comments for release notes are requested.

*https://jira.issues.couchbase.com/browse/MB-62793/[MB-62793]*::

Changes related to relaxing the maximum number of XATTRs in Couchbase have been implemented across various builds and commits. An attempt to create an index on 16 XATTR expressions was unsuccessful due to existing restrictions, even after some limitations were removed. Additionally, there is a distinction in handling XATTRs and document paths in certain projections, although mixing them is possible through the Go SDK's Lookupin API. Several commits across different build versions have addressed the issue (MB-62793), including fixing unit tests and resolving indentation for better merge compatibility. Users are advised to update release notes to inform customers about these changes and their resolutions.

*https://jira.issues.couchbase.com/browse/MB-63459/[MB-63459]*::

New to 7.7.0 is the ability to manipulate document extended attributes (xattrs) via common SQL++ statements.  

+

INSERT and UPSERT statement OPTIONS may now include an “xattrs” object element detailing additions and changes to the xattrs (omissions do not delete xattrs).  The UPDATE statement now supports SET and UNSET of meta().xattrs.{attribute} elements.


=== Eventing Service

[#dlist-known-issues-800-eventing-service]


*https://jira.issues.couchbase.com/browse/MB-64081/[MB-64081]*::

Eventing is not functioning correctly with App Services in cloud deployments due to an issue with the Sync Gateway registry parser failing to handle extra "config" objects in the "_sync" system xattr. This discrepancy does not occur in on-prem deployments. The Eventing team is investigating and patches are under review. The issue is linked to Sync Gateway 3.2 and Eventing version >=7.6.2, especially in Capella environments. Testing indicates that such setups were not extensively evaluated before release. Fixes are being implemented with plans to merge by November 5th and backport to version 7.6.4. Further tests are planned to prevent recurrence.


=== Backup Service

[#dlist-known-issues-800-backup-service]


*https://jira.issues.couchbase.com/browse/MB-62655/[MB-62655]*::

Couchbase versions 8.0.0-1845 and 8.0.0-1851 have incorporated commits [d5f37e7](https://github.com/couchbase/backup/commit/d5f37e7009db66717a777670cfba2573b1c49597) and [9ef94f7](https://github.com/couchbase/backup/commit/9ef94f739a5a6ddaee77cf816746cd88b1e86dfe) to create a query-report generator and properly build `cbqueryreportgen`. The title error in the report version 8.0.0-1992, regarding "Number of *Priority* Scans," should be corrected to "Number of *Primary* Scans." The same commits are repeatedly referenced in various builds of couchbase-columnar-1.2.0-1009, emphasizing the priority on creating and properly building the query-report generator, tracked under MB-62655.




=== Index Service

[#dlist-known-issues-800-index-service]


*https://jira.issues.couchbase.com/browse/MB-64982/[MB-64982]*::

When shard affinity is enabled, the indexer internally maps all replicas of an index to an alternateID. If such an alternateID exists on a node outside the list of nodes, instead of preventing replica creation, the system creates a new replica with the same alternateID on different nodes. This leads to rebalance failures on the affected nodes.
