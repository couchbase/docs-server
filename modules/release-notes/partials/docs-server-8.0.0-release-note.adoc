== Release 8.0 (August 2025)

Couchbase Server 8.0 was released in August 2025.
This maintenance release contains fixes to issues.

== Fixed Issues






=== Storage

[#dlist-known-issues-80-storage]


*https://jira.issues.couchbase.com/browse/MB-61385/[MB-61385]*::

The recent Couchbase update addresses the handling of invalid CAS values, introducing configurable modes like "error" and "replace" to manage CAS thresholds. The system can now either reject writes with out-of-bounds CAS values or regenerate a CAS value. A new "cas_value_invalid" status provides clearer error reporting. Two configuration parameters, `_hlc_invalid_strategy_` and `_dcp_hlc_invalid_strategy_`, allow different default behaviors for front-end operations and DCP replication. Discussions continue on managing compatibility and backward support, with a focus on avoiding data corruption and conflicts during replication. The default strategy for new buckets on 8.0 is set to "error," and further REST API enhancements are being considered for adjusting settings like the CAS threshold.

*https://jira.issues.couchbase.com/browse/MB-65644/[MB-65644]*::

Couchbase-server-8.0.0-2772 includes an indexing commit aimed at addressing MB-65644. This commit, identified by c8f3dab, changes the plasma configuration by setting enableCompressFullMarshal to false. The issue is scheduled to be closed in version 8.0.0-2905.






=== XDCR

[#dlist-known-issues-80-xdcr]


*https://jira.issues.couchbase.com/browse/MB-66140/[MB-66140]*::

The couchbase-server-8.0.0-3074 build includes a goxdcr update addressing MB-66140. This introduces the 'PipelineReinitHash' as a replication specification setting, ensuring that pipelines undergoing a `PipelineReinitStream` update do not resume from a checkpoint.




=== Eventing Service

[#dlist-known-issues-80-eventing-service]


*https://jira.issues.couchbase.com/browse/MB-64081/[MB-64081]*::

Eventing in Couchbase doesn't work with App Services due to a parsing issue in cloud deployments. The issue arises because the Sync Gateway registry object is enclosed within an additional "config" key, unlike in on-prem deployments. A patch has been developed and is under review, targeting a resolution by November 5th. The issue will be backported to version 7.6.4, and a specific smoke test for Capella is being added. Testing previously didn't cover the Capella environment, but adjustments are being made to include this environment in future tests.






=== Index Service

[#dlist-known-issues-80-index-service]


*https://jira.issues.couchbase.com/browse/MB-64982/[MB-64982]*::

When shard affinity is enabled, the indexer internally maps all replicas of an index to an alternateID. If such an alternateID exists on a node outside the list of nodes, instead of preventing replica creation, the system creates a new replica with the same alternateID on different nodes. This leads to rebalance failures on the affected nodes.
