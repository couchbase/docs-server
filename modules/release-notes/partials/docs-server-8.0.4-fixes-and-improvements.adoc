== Release 8.0.4 (November 2026)

Couchbase Server 8.0.4 was released in November 2026.
This maintenance release contains fixes for issues listed below.

=== Fixed Issues
{empty}

==== Cluster Manager

link:https://jira.issues.couchbase.com/browse/MB-73001[MB-73001]::
REST requests served from the Cluster Manager's response cache could stall for a long time when building a cached response took longer than its expiry time.
Client connections could be left in the `CLOSE_WAIT` state while the server waited for the cache.
The cache is now optimized so that slow response generation no longer blocks other requests.

link:https://jira.issues.couchbase.com/browse/MB-74417[MB-74417]::
When encryption at rest automatically encrypted a private key, the key was decrypted again for every inbound TLS connection.
Under high connection rates, this caused slow handshakes and lock contention.
This release removes the per-connection decryption cost.

link:https://jira.issues.couchbase.com/browse/MB-74902[MB-74902]::
On large clusters with many XDCR replications, `/pools/default` and bucket information REST requests could stall or return 5xx errors.
These endpoints now read node status from a snapshot instead of waiting on the Cluster Manager's node monitor.

link:https://jira.issues.couchbase.com/browse/MB-74905[MB-74905]::
A client that completed a TLS handshake on port 18091 and closed the connection without sending a request held a connection slot for about 5 minutes.
TLS health checks from load balancers and certificate-expiry probes connect in this way.
Once all slots were held, every request on port 18091 hung, while port 8091 kept working.
This issue is now resolved.

link:https://jira.issues.couchbase.com/browse/MB-74940[MB-74940]::
Parallel calls to `POST /node/controller/loadTrustedCAs`, as made by automated certificate rotation, could fail with HTTP 500 even when the CA was already trusted.
Scripts that stopped on the error could leave the cluster with a mix of old and new node certificates.
Parallel loads of the same CA now succeed.

link:https://jira.issues.couchbase.com/browse/MB-75133[MB-75133]::
The Index, Query and projector processes could crash after the Cluster Manager restarted.
This issue is now resolved.

==== Data Service

link:https://jira.issues.couchbase.com/browse/MB-74514[MB-74514]::
The Memcached process hangs when more than 100 external LDAP authentication requests are queued.
The front end stops serving connections while background tasks continue to run.
This release fixes the thread management to prevent the hang.

==== Eventing Service

link:https://jira.issues.couchbase.com/browse/MB-72728[MB-72728]::
For Eventing functions with Sync Gateway awareness enabled, writing checkpoint extended attributes did not preserve the document's expiry time.
Eventing now keeps the expiry of each mutation when it writes these attributes.

==== XDCR

link:https://jira.issues.couchbase.com/browse/MB-75148[MB-75148]::
XDCR now backs off when bucket information requests to the Cluster Manager respond slowly.
It also reuses local calls to the Cluster Manager when it checks replication pipelines.

link:https://jira.issues.couchbase.com/browse/MB-75152[MB-75152]::
On large deployments, XDCR could overload the target cluster's bootstrap node with `/pools/default` requests.
XDCR now adds backoff and jitter to remote cluster reference refreshes, caches the responses and removes duplicate calls.
