== Breaking changes 8.0 (August 2025)

Couchbase Server 8.0 was released in August 2025.
This maintenance release contains the following breaking changes:






=== Data Service

[#breaking-changes-80-data-service]


*https://jira.issues.couchbase.com/browse/MB-63946/[MB-63946]*::

When using `mcstat` it is no longer possible to use `--json=pretty`.
The request to pretty-print the JSON is ignored
+
Users can use a pipe in conjunction with an external formatting tool such as `jq` to obtain formatted output:
+
[source, shell]

----

./mcstat [options] --json [statgroup] \| jq .

----

*https://jira.issues.couchbase.com/browse/MB-63938/[MB-63938]*::

The recent update to Couchbase Server 8.0.0-1964 and Couchbase Columnar 1.2.0-1009 includes a crucial change to the mcstat utility. It now enforces the rule that only a single stat group can be queried at a time, addressing issue MB-63938. This change is designed to streamline operations and improve system performance. The updated implementation is part of the kv_engine commit 0e2fa3c. Users are encouraged to adapt their processes to accommodate this new limitation. The update aims to enhance operational clarity and efficiency for developers and administrators.

*https://jira.issues.couchbase.com/browse/MB-9418/[MB-9418]*::

Build couchbase-server-8.0.0 introduces a new "Secondary Warmup" feature, allowing the system to continue paging in items after reaching minimum thresholds, thus enhancing availability during warm-up. A new dynamic configuration parameter, "warmup_behavior," simplifies user interaction and replaces previous threshold settings. This parameter supports three modes: "blocking" (traditional behavior), "background" (faster write availability), and "none" (disabling warmup). The default behavior for new installations is 0% Primary and 100% Secondary warmup, offering quicker bucket availability. Users upgrading from previous versions will automatically shift to the new default, but can customize via "cbepctl" if needed. Testing supports these configurations, ensuring minimal wasted resources.

=== Views

[#breaking-changes-80-views]


*https://jira.issues.couchbase.com/browse/MB-67280/[MB-67280]*::

The Bucket Priority option has been removed from the CB Server UI due to changes in the task scheduler backend. This feature, which previously allowed tasks from certain buckets to be prioritized, has not been effective since version 7.0 because of the transition to Folly’s Executors for CPU and IO background tasks. The previous CB3ExecutorPool implementation used bucket priorities in scheduling algorithms, but this is not supported by the current FollyExecutorPool. Despite its removal from the UI, the option remains in the REST API for backward compatibility. With the increase in thread pool sizes since version 7.0, task scheduling performance has improved, reducing the need for bucket prioritization. This update is included in builds starting from couchbase-server-8.0.0-3506.

*https://jira.issues.couchbase.com/browse/MB-63212/[MB-63212]*::

The latest update removes the option to create memcached buckets from the UI. When users attempt to add a memcached bucket, no action occurs instead of an error being displayed. The change is implemented in Morpheus but not yet applied to older versions, where similar issues may arise. Although the backend may return an error message for other failures, it's unclear if the UI currently handles these effectively. The change has been confirmed and included in both Couchbase Server and Columnar builds. This release finalizes the removal of memcached buckets from the UI.

=== Index Service

[#breaking-changes-80-index-service]


*https://jira.issues.couchbase.com/browse/MB-63192/[MB-63192]*::

The latest build includes enhancements to the shard dealer for Couchbase, introducing support for multi-category shards with an emphasis on performance. Key improvements include transitioning to the maxDiskUsagePerShard config, refining the shard dealer code, and expanding tests across multiple passes. Additionally, the shard assignment algorithm has been updated for version 8.0, allowing more aggressive sharing of plasma shards, which may affect performance. The new distribution algorithm, which can be disabled via a feature flag, applies during rebalances in fully upgraded clusters. For on-prem deployments, file-based rebalance remains off by default. The release also addresses scenarios for handling vector indexes and the creation of additional shards depending on resources. Further performance tests are planned to assess the worst-case scenarios, following necessary parameter tuning.

=== Tools

[#breaking-changes-80-tools]


*https://jira.issues.couchbase.com/browse/MB-63389/[MB-63389]*::

The recent update removes support for creating memcached buckets in Couchbase CLI for versions 8.0 and above. Users attempting to create memcached buckets will encounter an error message advising the use of ephemeral buckets instead. This change is part of a broader effort to ensure version compatibility and maintainability, especially as Couchbase CLI becomes a separate component of the admin tools package. Commit validations for these updates have been made in build versions referenced for Couchbase server and columnar builds. Careful consideration of version checks will be integral to maintaining backward compatibility with older clusters.

*https://jira.issues.couchbase.com/browse/MB-60337/[MB-60337]*::

Previously, it was possible to remove backups which would cause dependent incremental backups to become invalid if they depended on those deleted backups. With this release, such deletes are prevented by default, but can be overridden with the new `--disable-safe-remove-check` flag.
