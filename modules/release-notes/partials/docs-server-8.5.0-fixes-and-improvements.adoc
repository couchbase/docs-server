[#release-8-5]
== Release 8.5 (October 2026)
Couchbase Server 8.5 was released in October 2026.
This maintenance release contains fixes to issues.

== Fixed Issues
{empty}

=== Cluster Manager

https://jira.issues.couchbase.com/browse/MB-73874[MB-73874]::

A new internal setting, internalIdentityPasswordCheckUnderMtls, requires valid credentials for the internal identity.
The setting is on by default in version 8.5.
Adding a node with client certificate authentication now requires the administrator's username and password.

https://jira.issues.couchbase.com/browse/MB-72985[MB-72985]::

The rebalanceMovesPerNode setting was removed from the `internalSettings` endpoint.
Users should use the settings/rebalance API instead.
This API supports values between 1 and 64.

https://jira.issues.couchbase.com/browse/MB-70951[MB-70951]::

The /metrics REST API incorrectly reported certain statistics twice.
The server now reports `cm_rest_request_enters_total` and `cm_rest_request_leaves_total` only once.

https://jira.issues.couchbase.com/browse/MB-70629[MB-69077]::

SDK Telemetry is now enabled by default for all users.

https://jira.issues.couchbase.com/browse/MB-70629[MB-70629]::

RBAC groups containing legacy roles were not migrated during upgrades or restores.
The system now replaces legacy security and admin roles with their modern equivalents.

https://jira.issues.couchbase.com/browse/MB-67280[MB-67280]::

The option to set bucket priority was removed from the UI.
The setting no longer affects system behavior due to changes in the task scheduler.

https://jira.issues.couchbase.com/browse/MB-67213[MB-67213]::

The Cache Miss Ratio metric was renamed to Get Miss Ratio in the UI.
This change clarifies that the metric measures failed read operations rather than cache performance.

https://jira.issues.couchbase.com/browse/MB-61479[MB-61479]::

The system now triggers an alert when an ephemeral bucket is reprovisioned.
This alert notifies users that a rebalance may be necessary to rebuild replicas.

=== Data Service

https://jira.issues.couchbase.com/browse/MB-74199[MB-74199]::

Documents with extended attributes could be streamed over DCP with an incorrect datatype bit.
The server now resets the Snappy bit when sending uncompressed payloads.

https://jira.issues.couchbase.com/browse/MB-72266[MB-72266]::

The Data Service no longer explicitly sets the socket receive buffer size by default.
The service now relies on the operating system's auto-tuning for socket buffers.

https://jira.issues.couchbase.com/browse/MB-70471[MB-70471]::

The `magma_max_default_storage_threads` and `magma_flusher_thread_percentage` bucket parameters were removed.
These values are now managed through `memcached` global settings.

https://jira.issues.couchbase.com/browse/MB-69568[MB-69568]::

The bucket state clients was renamed to references to better reflect its purpose.
A new stat `curr_bucket_connections` was introduced to track actual client connections.

https://jira.issues.couchbase.com/browse/MB-68779[MB-68779]::

The `kv_ep_commit_time_total_seconds` statistic was reported incorrectly due to a unit mismatch.
The underlying counter now uses microseconds to ensure accurate reporting.

https://jira.issues.couchbase.com/browse/MB-68379[MB-68379]::

The default list of TLS Cipher Suites was restricted to AES-256-GCM, AES-128-GCM, and CHACHA20-POLY1305.
This change removes support for SHA1 and CBC mode in TLS.

https://jira.issues.couchbase.com/browse/MB-61385[MB-61385]::

The system now fails operations with a CAS value that exceeds the future threshold.
This prevents faulty CAS values from distorting the `vbucket` `max_cas` and affecting conflict resolution.

=== Search Service

https://jira.issues.couchbase.com/browse/MB-70770[MB-70770]::

Discrepancies in document counts between Search and KV could occur during rare failover scenarios.
The Search service now includes guards to prevent stale events from being processed.

https://jira.issues.couchbase.com/browse/MB-70388[MB-70388]::

The Search service now sets `docvalues` for `geopoint` fields internally.
This fix prevents high query latency caused by calculating values on demand.

https://jira.issues.couchbase.com/browse/MB-69751[MB-69751]::

A Search index can now source data from at most 100 collections by default.
Creating or editing an index that exceeds this limit returns an error.

https://jira.issues.couchbase.com/browse/MB-69655[MB-69655]::

Normalization of multiple vectors in a single field was corrected for cosine similarity.
The Search engine now treats multiple vectors in the same field as independent entities.

https://jira.issues.couchbase.com/browse/MB-69654[MB-69654]::

The Search engine now distinguishes between normal and nested field mappings with the same name.
This allows fields at different levels to be configured independently.

https://jira.issues.couchbase.com/browse/MB-69641[MB-69641]::

Vector search now returns the top K documents instead of the top K vectors.
Each document appears at most once and is scored by its best-matching vector.

https://jira.issues.couchbase.com/browse/MB-68681[MB-68681]::

The number of Search index partitions is now capped at the number of vBuckets in the source bucket.
This prevents service crashes caused by excessively high partition counts.

https://jira.issues.couchbase.com/browse/MB-67016[MB-67016]::

Hyperscale Vector Index queries could return fewer results than the requested LIMIT.
Users should increase `nprobes` or `topNScan` if results are capped unexpectedly.

https://jira.issues.couchbase.com/browse/MB-55637[MB-55637]::

The Search service no longer exits with a fatal error when disk space is full.
Errors during persistence or cleanup are now logged while the service remains available.

=== Tools

https://jira.issues.couchbase.com/browse/MB-70255[MB-70255]::

A bug was fixed where merging backups failed for buckets with cross-cluster versioning enabled.
The backup tool now handles these buckets during merge operations.

https://jira.issues.couchbase.com/browse/MB-68392[MB-68392]::

The backup tool now checks for required cloud permissions before performing WORM operations.
A warning is printed if the identity lacks permissions for object versioning or locking.

=== XDCR

https://jira.issues.couchbase.com/browse/MB-71476[MB-71476]::

Rebalanced-out nodes could use stale manifests if buckets were re-created while the node was away.
Upgraded clusters now handle these scenarios to prevent data backfill issues.

https://jira.issues.couchbase.com/browse/MB-71244[MB-71244]::

A race condition was fixed that could cause goroutines to hang during replication pause or deletion.
This occurred when replications required a rollback to zero after a failover.

https://jira.issues.couchbase.com/browse/MB-70844[MB-70844]::

XDCR incorrectly skipped mutations when a target document was locked.
The replication logic was updated to identify locked documents and retry the operation.

https://jira.issues.couchbase.com/browse/MB-70444[MB-70444]::

XDCR replications between Couchbase Server Community Edition clusters are now strictly prohibited.
Existing CE-to-CE replications are paused and cannot be resumed.

https://jira.issues.couchbase.com/browse/MB-68340[MB-68340]::

New replication settings were introduced to throttle DCP flow control and `async` events.
The internal settings `UprFeedDataChanLength` and `UprFeedBufferSize` are now deprecated.
