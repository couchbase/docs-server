== Release 8.0 (August 2025)

Couchbase Server 8.0 was released in August 2025.
This maintenance release contains fixes to issues.

== What's New






=== Storage

[#dlist-known-issues-80-storage]


*https://jira.issues.couchbase.com/browse/MB-60542/[MB-60542]*::

The build couchbase-server-8.0.0-1545 includes a kv_engine commit identified by fd8914a. This commit focuses on parsing and dumping "deprecated" and "notes" fields as described in MB-60542. The same commit is part of the couchbase-columnar-1.2.0-1009 build. Both builds ensure these fields are processed, as detailed in the linked commit message and the corresponding issue tracking MB-60542 on Jira.


=== Data Service

[#dlist-known-issues-80-data-service]


*https://jira.issues.couchbase.com/browse/MB-62295/[MB-62295]*::

Build couchbase-server-8.0.0-1668 includes the kv_engine commit [db74893](https://github.com/couchbase/kv_engine/commit/db74893ff4dda84876a821364317b4627437758e) with the message: "MB-62295: Use symbolic link for audit.log." This change has been validated on build 8.0.0-2236, and the ticket has been closed. A symbolic link is used for the current audit log, redirected to a specific file. There is a request for adding this information to the release notes. The repeated request emphasizes summarizing the change for communication purposes.






=== Query Service

[#dlist-known-issues-80-query-service]


*https://jira.issues.couchbase.com/browse/MB-62793/[MB-62793]*::

The original limit of one XATTR per KV op was relaxed to a maximum of 16 in KV server version 7.6; this ticket explores extending that relaxation to queries.
+
With this change, users can:


. Use up to 15 XATTR fields in their query.


. CREATE INDEX no longer imposes a limit on the number of XATTR fields that can be indexed.

*https://jira.issues.couchbase.com/browse/MB-63459/[MB-63459]*::

New to 7.7.0 is the ability to manipulate document extended attributes (xattrs) via common SQL++ statements.  

+

INSERT and UPSERT statement OPTIONS may now include an “xattrs” object element detailing additions and changes to the xattrs (omissions do not delete xattrs).  The UPDATE statement now supports SET and UNSET of meta().xattrs.{attribute} elements.
