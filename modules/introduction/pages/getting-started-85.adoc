= Getting Started with Couchbase Server 8.5
:description: Download, install, and take your first steps with Couchbase Server 8.5.

[abstract]
{description}

Couchbase Server 8.5 brings native encryption at rest for protecting data on disk without application changes, continuous backup with point-in-time restore for near-zero data loss, rank fusion for combining vector, full-text, and {sqlpp} results in a single hybrid search, and binary quantization for faster, more memory-efficient vector indexes, along with a range of other enhancements.

To take advantage of all of these, launch a cluster with the Data, Index, Query, and Search services enabled, and use the xref:learn:buckets-memory-and-storage/storage-engines.adoc[Magma] storage engine for your buckets. Continuous backup and PITR need Magma buckets, and hybrid search with rank fusion and binary quantization needs the Query, Index, and Search services working together.

=== Install from a container image

The xref:install:getting-started-docker.adoc[Docker install guide] assumes you `docker run` an image pulled from Docker Hub.
Since the private preview build isn't published to a public registry yet, you instead get a downloadable image archive (a `.tar` file) as part of the download bundle above: one `-docker.tar` file for a regular Docker Hub-style image, and one `-rhcc.tar` file in Red Hat Certified Container format.

. Download the archive for your platform and architecture.
. Load it into Docker:
+
[source,console]
----
$ docker load -i couchbase-server-enterprise_8.5.0-1257-linux_amd64-docker.tar
----
. Confirm the image loaded:
+
[source,console]
----
$ docker images
----
. Run and set up the container the same way as the xref:install:getting-started-docker.adoc[Docker install guide].

If you're deploying with Kubernetes using the xref:operator:ROOT:overview.adoc[Couchbase Autonomous Operator], tag and push the loaded image to your own internal or private registry, then point your `couchbase-cluster.yaml` at it.
