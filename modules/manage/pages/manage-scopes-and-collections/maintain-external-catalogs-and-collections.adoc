= Maintain External Catalogs and Collections
:description: List, alter, and drop external catalogs and external collections after you create them.
:page-edition: Enterprise Edition
:page-toclevels: 3

[abstract]
{description}

After you xref:manage:manage-scopes-and-collections/create-external-catalogs-and-collections.adoc[create an external catalog and collection], you can list them, change a catalog's connection details, or remove them entirely.
You manage external catalogs and collections through the REST API and {sqlpp} only.

== Prerequisites

* An existing external catalog or external collection to maintain.
* The External Catalog Admin role to alter or drop a catalog.
The Manage Scopes role, Bucket Admin role, or Full Admin role to alter or drop a collection.

== Procedure

=== List External Catalogs and Collections

. Query the `system:catalogs` keyspace to list every external catalog on the cluster.
+
[source,sql]
----
SELECT c.* FROM system:catalogs AS c;
----

. Query the `system:keyspaces` keyspace, filtered to keyspaces with a `catalog` field, to list every external collection.
+
[source,sql]
----
SELECT k.* FROM system:keyspaces AS k WHERE k.catalog IS NOT MISSING;
----
+
You can also list catalogs with `GET /pools/default/externalCatalogs` and external collections with `GET /pools/default/buckets/{bucket}/scopes/?external=1`.

=== Alter an External Catalog

. Change a catalog's connection details with the `ALTER CATALOG` statement.
You can update any option in the `WITH` clause, such as `uri`, `warehouse`, or a signing region.
+
[source,sql]
----
ALTER CATALOG sales_catalog WITH { "warehouse": "s3://sales-bucket/warehouse2" };
----
+
NOTE: You cannot change a catalog's name, type, or source after you create it.
Attempting to change `catalogSource` fails with `"Invalid option 'catalogSource'"` (error 12038).
To switch to a different catalog source, drop the catalog and create it again.

=== Alter an External Collection

. Change a collection's settings with the `ALTER COLLECTION` statement.
+
[source,sql]
----
ALTER COLLECTION `sales`.`_default`.`orders` WITH { "decimal-to-double": true };
----
+
You can alter any of the collection's optional settings this way, including `decimal-to-double` and `parallelScans`, without dropping and re-creating the collection.

=== Drop an External Collection

. Drop the collection with a standard `DROP COLLECTION` statement.
+
[source,sql]
----
DROP COLLECTION `sales`.`_default`.`orders`;
----
+
Dropping an external collection works exactly like dropping a regular collection.
It does not affect the catalog or credentials the collection referenced.
Both remain intact and reusable afterward.

=== Drop an External Catalog

. Drop the catalog with a standard `DROP CATALOG` statement.
+
[source,sql]
----
DROP CATALOG sales_catalog;
----
+
WARNING: Dropping a catalog does not cascade to any external collections that still reference it, and nothing prevents you from dropping a catalog that still has dependents.
Once the drop finishes propagating, a query against an orphaned collection fails immediately with `"Catalog information not found for external collection"`.
If you're removing an integration entirely, drop its dependent external collections first, then the catalog, then any credentials you no longer need.
