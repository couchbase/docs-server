= JWT Authentication
:description: pass:q[Couchbase Server can accept a signed token from an identity provider in place of a username and password.]

[abstract]
{description}

[.edition]#{enterprise}#

A _JSON Web Token_ (JWT) is a short block of text that an identity provider (IdP) signs and gives to a user or application.
Presenting the token proves who you are, so you do not need to send a password to Couchbase Server.

Once you enable JWT authentication, you can use a token to reach:

* The Couchbase Server Web Console
* Client applications built with the Couchbase SDKs
* `couchbase-cli` commands
* The REST API

To understand how JWT authentication works and how it compares to the other methods, see xref:learn:security/external-authentication.adoc#jwt-overview[JSON Web Token (JWT) Authentication].

== Before You Start

Couchbase Server does not issue tokens of its own.
You need an identity provider that does, such as Keycloak, Okta, or Microsoft Entra ID.

Tokens are signed but not encrypted.
Anyone who intercepts a token can read it and reuse it until it expires, so *always use TLS-encrypted connections with JWT authentication*.

== Set Up JWT Authentication

Work through these pages in order.

. xref:manage:manage-security/configure-jwt-issuer.adoc[Configure a JWT Issuer]
+
Tell Couchbase Server about your identity provider: where to find its signing key, how its tokens are shaped, and which user each token refers to.
You need at least one issuer before anyone can sign in with a token.

. xref:manage:manage-security/jwt-roles-and-groups.adoc[Assign Roles and Groups from a Token]
+
Optional.
Let the identity provider decide what a user can do in Couchbase Server, instead of creating each user in Couchbase Server yourself.

. xref:manage:manage-security/configure-jwt-sso.adoc[Set Up Single Sign-On for the Web Console]
+
Optional.
Add a button to the Web Console sign-in page that sends users to your identity provider to sign in.

. xref:manage:manage-security/authenticate-using-jwt.adoc[Authenticate Using a JWT]
+
Use a token from the Web Console, the REST API, the CLI, and client applications.

If sign-ins fail, see xref:manage:manage-security/troubleshoot-jwt.adoc[Troubleshoot JWT Authentication].
