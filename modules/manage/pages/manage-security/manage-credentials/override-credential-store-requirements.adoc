= Override Credential Store Requirements
:description: You can override the credential store's security requirements of node-to-node encryption and encryption at rest for configuration files.
:page-toclevels: 2
:page-edition: Enterprise Edition

[abstract]
{description}
These requirements are vital for maintaining the security of credentials in the credential store.
You should only override them in non-production environments such as testing or development. 

You may want to override these requirements if you have credentials in the credential store and need to turn off encryption at rest for configuration files.
By default, Couchbase Server prevents you from turning off this encryption if you have credentials in the credential store because it leaves your stored credentials unencrypted.
By overriding the encryption-at-rest requirement, Couchbase Server no longer prevents you from turning off encryption at rest for configuration files.

For more information about the security requirements, see xref:manage:manage-security/manage-credentials/manage-credential-store.adoc#prerequisites[Prerequisites] in xref:manage:manage-security/manage-credentials/manage-credential-store.adoc[].

CAUTION: Overriding the credential store's security requirements can expose authentication secrets such as bearer tokens, keys, and passwords.

== Prerequisites

* Your user account must have the xref:learn:security/roles.adoc#full-admin[Full Admin] or xref:learn:security/roles.adoc#security-admin[Security Admin] role to override the requirements.

[#override-requirements]
== Override the Requirements

To override the credential store's security requirements, make a `PUT` request to `/settings/credentialStore`.

This endpoint supports 2 override values, 1 for each of the security requirements:

* `configEncryptionOverride` overrides the encryption at rest requirement.
* `n2nEncryptionOverride` overrides the node-to-node encryption requirement.

You must set both parameters, even if you only want to override 1 requirement.
Set a parameter to `true` to override its requirement, or `false` to enforce it.

This endpoint requires a JSON request body.
It does not accept form-encoded parameters.

For detailed information about overriding the requirements using the REST API, see xref:rest-api:security/credential-store/override-requirements.adoc#set-override[Override the Requirements].

[source,bash]
----
curl -u $CB_USER:$CB_PASS -X PUT \
     http://$CB_HOST:$CB_PORT/settings/credentialStore \
     -H 'Content-Type: application/json' \
     -d '{"configEncryptionOverride": <true|false>, "n2nEncryptionOverride": <true|false>}'
----

This example overrides the node-to-node encryption requirement, while leaving the configuration encryption requirement enabled:

[source,bash]
----
curl -u $CB_USER:$CB_PASS -X PUT \
     http://$CB_HOST:$CB_PORT/settings/credentialStore \
     -H 'Content-Type: application/json' \
     -d '{"configEncryptionOverride": false, "n2nEncryptionOverride": true}' | jq
----

The call returns the new settings:

[source,json]
----
{
  "configEncryptionOverride": true,
  "n2nEncryptionOverride": true
}
----

[#view-override-settings]
== View the Current Override Settings

To view the current override settings, make a `GET` request to `/settings/credentialStore`:

For detailed information about viewing the current override settings using the REST API, see xref:rest-api:security/credential-store/override-requirements.adoc#view-override[View the Current Override Settings].

[source,bash]
----
curl -u $CB_USER:$CB_PASS \
http://$CB_HOST:$CB_PORT/settings/credentialStore | jq
----

If you have not overridden the requirements, the call returns both settings as `false`:

[source,json]
----
{
  "configEncryptionOverride": false,
  "n2nEncryptionOverride": false
}
----

If the credential store contains 1 or more credentials, and an overridden requirement leaves those credentials unprotected, the response also includes a `warnings` array:

[source,json]
----
{
  "warnings": [
    "Stored credentials risk being sent unencrypted unless node-to-node encryption is enabled on every node in the cluster"
  ],
  "n2nEncryptionOverride": true,
  "configEncryptionOverride": false
}
----

NOTE: Couchbase Server only returns a warning for a requirement that's both overridden and currently unmet, and only when the credential store contains at least 1 credential.
Overriding a requirement while the credential store is empty does not produce a warning.

[#remove-override]
== Reset the Requirements to Their Defaults

To remove your overrides and enforce both requirements again, make a `DELETE` request to `/settings/credentialStore`:

For detailed information about resetting the requirements using the REST API, see xref:rest-api:security/credential-store/override-requirements.adoc#reset-override[Reset the Requirements to Their Defaults].

[source,bash]
----
curl -u $CB_USER:$CB_PASS -X DELETE http://$CB_HOST:$CB_PORT/settings/credentialStore
----

This has the same effect as setting both `configEncryptionOverride` and `n2nEncryptionOverride` to `false`.
