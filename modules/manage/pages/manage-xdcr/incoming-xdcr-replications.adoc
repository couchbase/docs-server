= Incoming Replications
:description: pass:q[]
:page-toclevels: 2

[abstract]
{description}

When a replication is created, the target cluster is identified as such.

A cluster is identified as a target cluster in XDCR when it receives replicated data from a remote cluster.
Then the replicating remote cluster is identified as a source cluster.

[#view-incoming-replications]
== View Incoming Replications

On the XDCR UI, if the cluster is a target for XDCR replications from remote clusters, the Incoming Replications section lists the incoming replications, grouped by the remote cluster name.
Expand *Incoming Replications* to see the details of any incoming replications created on the remote cluster.

There may not be any replications listed if the remote cluster has not yet created a replication.
However, the remote cluster name is listed because the remote cluster has added this cluster's connection details to its XDCR cluster references.

image::manage-xdcr/incoming-replications-on-target.png[,800,align=left]

The information for the above incoming replications is retrieved using the REST API.
See xref:rest-api:rest-xdcr-list-incoming-replications.adoc#complete-response[Cluster with replication specifications - a full example].

To get the incoming replications information using the REST API, see xref:rest-api:rest-xdcr-list-incoming-replications.adoc[Listing Incoming Replications].

== Calculating Incoming XDCR Connections

You can calculate the number of incoming XDCR connections for a replication with the following formula.

----
(target_nozzle_per_node) * 2 * (number of Data nodes on the source cluster) * (number of Data nodes on the target cluster)
----

The formula details are as follows:

* `target_nozzle_per_node` is the incoming replication's target_nozzle_per_node.

* `number of Data nodes on the source cluster` is the number of Data nodes in the remote cluster that the replication is coming from (the SourceClusterNodes in the incoming replications information).

* `number of Data nodes on the target cluster` is the number of Data nodes in the current cluster, the target of the incoming replication.

== Source Cluster Heartbeat Interval

Incoming replications information relies on heartbeats sent from the source cluster to the target cluster.
For this reason, these source cluster heartbeats are also referred to as target awareness heartbeats.
The incoming replication information displays on the UI and you can retrieve it by the `GET /xdcr/sourceClusters` REST API.
For more information, see xref:rest-api:rest-xdcr-list-incoming-replications.adoc[Listing Incoming Replications].

The source cluster controls the interval for sending source cluster heartbeats.
By default, the heartbeat interval can range from one to five minutes, depending on replication activity.
The heartbeat interval determines the refresh rate of the incoming replication information on the target cluster.

The source cluster heartbeats are sent as soon as the target remote cluster reference is created on the source, even if no replications exist yet.
In this scenario, the incoming replication view on the target cluster shows only the source cluster information.
For the REST API example response, see xref:rest-api:rest-xdcr-list-incoming-replications.adoc#example-source-without-replication-specs[A cluster without replication specifications].

When source replication exists, the incoming replication view on the target cluster shows the source cluster information and its replication specifications.
For the REST API example response with a replication specification, see xref:rest-api:rest-xdcr-list-incoming-replications.adoc#example-source-with-replication-specs[A cluster with replication specifications].

If the source and target clusters are the same, target awareness heartbeats are not sent, and incoming replication information for that cluster does not appear.
