= Enable and Disable WORM for a Repository
:page-status: Couchbase Server 8.5
:description: The Backup Service REST API lets you enable Write-Once-Read-Many (WORM) for a repository and remove its WORM configuration once the configuration has expired.

[abstract]
{description}

[#http-methods-and-uris]
== HTTP Method and URI

----
POST /cluster/self/repository/active/<repository-id>/worm
----

[#description]
== Description

WORM protection stops anyone from modifying or deleting a backup until its compliance period ends.
Use this endpoint to enable WORM for an existing repository, or to remove the WORM configuration of a repository after it has expired.

WORM protects only the backups that you create after you enable it.
You can enable WORM only when the repository has no valid WORM configuration.
If the WORM validity period of the repository has not expired, the request fails.

NOTE: You must xref:rest-api:backup-pause-and-resume-tasks.adoc[pause the repository] before you call this endpoint.

[#curl-syntax]
== Curl Syntax

----
curl -X POST http://<backup-node-ip-address-or-domain-name>:8097/cluster/self/repository/active/<repository-id>/worm \
  -u <username>:<password> \
  -d '{"period": <days>}'
----

The username and password must identify an administrator with the Full Admin role.
In the URI, `<repository-id>` is the ID of the repository.

The request body is a JSON object that contains one of the following fields:

* `period`.
An integer that specifies, in days, the WORM compliance period for new backups.
The range is `3` to `36525`.
* `disable`.
A boolean.
Specify `true` to remove the WORM configuration.

Do not specify both fields in the same request.

IMPORTANT: You can disable WORM only after the WORM validity period of the repository expires.
Enabling WORM sets this period to 28 days, and each new WORM-protected backup can extend it.

[#responses]
== Responses

If the call succeeds, the Backup Service returns a success status code.

If the request is not valid, the call fails and the response contains an error message.
For example, the call fails when you enable WORM on a repository whose WORM validity period has not expired.

[#examples]
== Examples

The following call enables WORM for the repository `backup-repo-01`, with a compliance period of 90 days:

----
curl -X POST http://backup-node1.example.com:8097/cluster/self/repository/active/backup-repo-01/worm \
  -u Administrator:password \
  -d '{"period": 90}'
----

Backups that you create in the repository after this call are WORM-protected for 90 days.

The following call removes the WORM configuration from `backup-repo-01`.
The call succeeds only after the WORM validity period of the repository has expired.

----
curl -X POST http://backup-node1.example.com:8097/cluster/self/repository/active/backup-repo-01/worm \
  -u Administrator:password \
  -d '{"disable": true}'
----
