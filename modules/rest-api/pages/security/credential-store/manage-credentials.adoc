== Description

These APIs let you list, view, create, update, and delete credentials in the credential store.
For more information, see xref:learn:security/credential-store.adoc[].

Every credential has a `type`, such as `aws` or `http`, which determines which external service and authentication protocols it uses.
The `type` determines the required and optional fields in the request body's `fields` object.
For the literal `type` values and their required and optional fields, see <<#type-fields>>.

NOTE: Before calling these endpoints, your cluster must have the credential store enabled.  
For more information, see xref:manage:manage-security/manage-credentials/manage-credential-store.adoc#prerequisites[Prerequisites].

[[list-credentials]]
== List Credentials

List every credential in the credential store, or only the credentials whose ID starts with a specific prefix.

.List All Credentials
----
GET /settings/credentials
----

.List Credentials Matching a Prefix
----
GET /settings/credentials?prefix={PREFIX}
----

=== curl Syntax

[source,bash]
----
curl -u $USER:$PASSWORD -X GET \
     'http://{HOST}:{PORT}/settings/credentials[?prefix={PREFIX}]'
----

.Query Parameters
`PREFIX` (optional)::
Only return credentials whose ID starts with this value.

.*Path Parameters*
:priv-link: list-privs
include::partial$user-pw-host-port-params.adoc[]

[[list-privs]]
=== Required Privileges

You must have at least 1 of the following roles:

* xref:learn:security/roles.adoc#full-admin[Full Admin]
* xref:learn:security/roles.adoc#credential-admin[Credential Admin]
* xref:learn:security/roles.adoc#security-admin[Security Admin]
* xref:learn:security/roles.adoc#ro-security-admin[Read-Only Security Admin]

=== Responses

`200 OK`::
Returns a JSON object containing a `credentials` array.
See <<#list-example>> for the schema of the output.
Sensitive fields in every credential are redacted as `********`.

`400 Bad Request`::
Returned if the `PREFIX` query parameter contains a character that is not valid in a credential ID.

`403 Forbidden`::
Returned if the user does not have 1 of the roles listed in <<#list-privs>>.

[#list-example]
=== Examples

The following example lists every credential whose ID starts with `iceberg/`:

[source,bash]
----
curl -u Administrator:password -X GET \
     'http://127.0.0.1:8091/settings/credentials?prefix=iceberg/' | jq
----

The JSON returned by this command lists the matching credentials:

[source,json]
----
{
  "credentials": [
    {
      "id": "iceberg/aws/sales-data",
      "type": "aws",
      "schemaVersion": 1,
      "description": "S3 access for the sales-data Iceberg table",
      "fields": {
        "accessKeyId": "AKIAIOSFODNN7EXAMPLE",
        "secretAccessKey": "********",
        "region": "us-east-1"
      },
      "guardrails": {
        "allowedServices": ["n1ql"]
      },
      "meta": {
        "createdAt": 1789571311190,
        "createdBy": {"user": "Administrator", "domain": "admin"}
      }
    }
  ]
}
----

[[get-credential]]
== Get a Credential

Get the details of a single credential.

.Get a Credential
----
GET /settings/credentials/{CREDENTIAL_ID}
----

=== curl Syntax

[source,bash]
----
curl -u $USER:$PASSWORD -X GET \
     'http://{HOST}:{PORT}/settings/credentials/{CREDENTIAL_ID}'
----

.*Path Parameters*
:priv-link: get-privs
include::partial$user-pw-host-port-params.adoc[]

`CREDENTIAL_ID`::
The `id` of the credential you want to view.

[[get-privs]]
=== Required Privileges

You must have at least 1 of the following roles:

* xref:learn:security/roles.adoc#full-admin[Full Admin]
* xref:learn:security/roles.adoc#credential-admin[Credential Admin]
* xref:learn:security/roles.adoc#security-admin[Security Admin]
* xref:learn:security/roles.adoc#ro-security-admin[Read-Only Security Admin]

`200 OK`::

`403 Forbidden`::

[[create-credential]]
== Create a Credential

Create a new credential in the credential store.

.Create a Credential
----
POST /settings/credentials/{CREDENTIAL_ID}
----

=== curl Syntax

[source,bash]
----
curl -u $USER:$PASSWORD -X POST \
     'http://{HOST}:{PORT}/settings/credentials/{CREDENTIAL_ID}' \
     -H 'Content-Type: application/json' \
     -d '{
           "type": "<TYPE>",
           "description": "<DESCRIPTION>",
           "expiresAt": <EPOCH_MS>,
           "fields": {
             <TYPE_SPECIFIC_FIELDS>
           },
           "guardrails": {
             <GUARDRAIL_FIELDS>
           }
         }'
----

.*Path Parameters*
:priv-link: create-privs
include::partial$user-pw-host-port-params.adoc[]

`CREDENTIAL_ID`::
The ID you want to assign to the new credential.
Can be up to 128 printable ASCII characters.

.*Fields*

`type` (string, required)::
The credential's type.
For the supported values, see <<#type-fields>>.

`fields` (object, required)::
The credential's type-specific fields.
The required and optional fields depend on the `type` value.

`description` (string, optional)::
A human-readable description of the credential.

`expiresAt` (integer, optional)::
The credential's expiration timestamp, in milliseconds since the Unix epoch.
Must be at least 5 minutes in the future.

`guardrails` (object, optional)::
Restrictions on how a service can use the credential on a user's behalf.
For the supported fields, see xref:manage:manage-security/manage-credentials/manage-credential-store.adoc#guardrails-object[Guardrails Object].

[[create-privs]]
=== Required Privileges

You must have at least 1 of the following roles:

* xref:learn:security/roles.adoc#full-admin[Full Admin]
* xref:learn:security/roles.adoc#credential-admin[Credential Admin]
* xref:learn:security/roles.adoc#security-admin[Security Admin]

=== Responses

`201 Created`::
Returns a JSON object containing the new credential's details.
See <<#create-example>> for the schema of the output.

`400 Bad Request`::
Returned when the request body is invalid, such as an invalid `type` value, a missing required field, or an `expiresAt` value that is not at least 5 minutes in the future.
Also returned if the credential store's encryption requirements are not met and have not been overridden.
For example:
+
[source,json]
----
{
  "error": "Credential store requires config encryption at rest to be enabled, or configEncryptionOverride to be set in /settings/credentialStore"
}
----

`403 Forbidden`::
Returned if the user does not have 1 of the roles listed in <<#create-privs>>.

`409 Conflict`::
Returned if a credential with this `CREDENTIAL_ID` already exists.

[#create-example]
=== Examples

The following example creates an AWS credential for accessing an S3 bucket used by an Apache Iceberg external collection:

[source,bash]
----
curl -u Administrator:password -X POST \
     'http://127.0.0.1:8091/settings/credentials/iceberg/aws/sales-data' \
     -H 'Content-Type: application/json' \
     -d '{
           "type": "aws",
           "description": "S3 access for the sales-data Iceberg table",
           "fields": {
             "accessKeyId": "AKIAIOSFODNN7EXAMPLE",
             "secretAccessKey": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
             "region": "us-east-1"
           },
           "guardrails": {
             "allowedServices": ["n1ql"]
           }
         }' | jq
----

The JSON returned by this command shows the new credential, with its sensitive field redacted:

[source,json]
----
{
  "id": "iceberg/aws/sales-data",
  "type": "aws",
  "schemaVersion": 1,
  "description": "S3 access for the sales-data Iceberg table",
  "fields": {
    "accessKeyId": "AKIAIOSFODNN7EXAMPLE",
    "secretAccessKey": "********",
    "region": "us-east-1"
  },
  "guardrails": {
    "allowedServices": ["n1ql"]
  },
  "meta": {
    "createdAt": 1789571311190,
    "createdBy": {"user": "Administrator", "domain": "admin"}
  }
}
----

[[update-credential]]
== Update a Credential

Replace an existing credential's material, using the same method you use to create a credential.

.Update a Credential
----
PUT /settings/credentials/{CREDENTIAL_ID}
----

CAUTION: This is a full-replacement operation.
Every field you do not include in the request, other than `createdAt` and `createdBy`, is removed from the credential.
You must resupply every field you want to keep, including sensitive fields such as `secretAccessKey`, even if you are not changing their values.

=== curl Syntax

[source,bash]
----
curl -u $USER:$PASSWORD -X PUT \
     'http://{HOST}:{PORT}/settings/credentials/{CREDENTIAL_ID}' \
     -H 'Content-Type: application/json' \
     -d '{
           "type": "<TYPE>",
           "description": "<DESCRIPTION>",
           "expiresAt": <EPOCH_MS>,
           "fields": {
             <TYPE_SPECIFIC_FIELDS>
           },
           "guardrails": {
             <GUARDRAIL_FIELDS>
           }
         }'
----

.*Path Parameters*
:priv-link: update-privs
include::partial$user-pw-host-port-params.adoc[]

`CREDENTIAL_ID`::
The `id` of the credential you want to update.

.*Fields*

`type` (string, required)::
The credential's type.
This value is immutable — it must match the credential's existing `type`.
To change a credential's type, delete and recreate the credential, instead.

`fields` (object, required)::
The credential's type-specific fields.
See <<#create-credential>> for details.

`description`, `expiresAt`, `guardrails` (optional)::
See <<#create-credential>> for details.
Omitting any of these removes it from the credential.

[[update-privs]]
=== Required Privileges

You must have at least 1 of the following roles:

* xref:learn:security/roles.adoc#full-admin[Full Admin]
* xref:learn:security/roles.adoc#credential-admin[Credential Admin]
* xref:learn:security/roles.adoc#security-admin[Security Admin]

=== Responses

`200 OK`::
Returns a JSON object containing the updated credential's details.
See <<#update-example>> for the schema of the output.

`400 Bad Request`::
Returned when the request body is invalid, or when `type` does not match the credential's existing type:
+
[source,json]
----
{
  "error": "Credential type is immutable and cannot be changed; delete and recreate the credential to change its type"
}
----

`403 Forbidden`::
Returned if the user does not have 1 of the roles listed in <<#update-privs>>.

`404 Object Not Found`::
Returned if `CREDENTIAL_ID` does not match the ID of an existing credential.

`409 Conflict`::
Returned if you supplied a `payloadVersion` field that no longer matches the credential's current revision.

[#update-example]
=== Examples

The following example changes the `region` of the `iceberg/aws/sales-data` credential.
The `accessKeyId` and `secretAccessKey` are unchanged, but must still be included:

[source,bash]
----
curl -u Administrator:password -X PUT \
     'http://127.0.0.1:8091/settings/credentials/iceberg/aws/sales-data' \
     -H 'Content-Type: application/json' \
     -d '{
           "type": "aws",
           "description": "S3 access for the sales-data Iceberg table",
           "fields": {
             "accessKeyId": "AKIAIOSFODNN7EXAMPLE",
             "secretAccessKey": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
             "region": "eu-west-1"
           },
           "guardrails": {
             "allowedServices": ["n1ql"]
           }
         }' | jq
----

[[patch-credential]]
== Partially Update a Credential

Update a credential's `description`, `expiresAt`, or `guardrails` without resupplying its type-specific fields.

.Partially Update a Credential
----
PATCH /settings/credentials/{CREDENTIAL_ID}
----

You must include at least 1 of `description`, `expiresAt`, or `guardrails` in the request.
Any of these you leave out of the request keeps its current value.
To rotate a credential's material, use <<#update-credential>>, instead.

CAUTION: The `guardrails` field is a whole-object replacement, not a merge.
If you include `guardrails` in the request, it replaces the credential's entire existing `guardrails` object.
To add a value to an existing guardrail without losing the rest of it, include the complete guardrails object you want the credential to have, not just the value you're adding.

=== curl Syntax

[source,bash]
----
curl -u $USER:$PASSWORD -X PATCH \
     'http://{HOST}:{PORT}/settings/credentials/{CREDENTIAL_ID}' \
     -H 'Content-Type: application/json' \
     -d '{
           "description": "<DESCRIPTION>",
           "expiresAt": <EPOCH_MS>,
           "guardrails": {
             <GUARDRAIL_FIELDS>
           }
         }'
----

.*Path Parameters*
:priv-link: patch-privs
include::partial$user-pw-host-port-params.adoc[]

`CREDENTIAL_ID`::
The `id` of the credential you want to update.

.*Fields*

`description`, `expiresAt`, `guardrails` (optional, at least 1 required)::
See <<#create-credential>> for details.
Set any of these to JSON `null` to remove it from the credential.

[[patch-privs]]
=== Required Privileges

You must have at least 1 of the following roles:

* xref:learn:security/roles.adoc#full-admin[Full Admin]
* xref:learn:security/roles.adoc#credential-admin[Credential Admin]
* xref:learn:security/roles.adoc#security-admin[Security Admin]

=== Responses

`200 OK`::
Returns a JSON object containing the updated credential's details.

`400 Bad Request`::
Returned if the request body does not include at least 1 of `description`, `expiresAt`, or `guardrails`:
+
[source,json]
----
{
  "error": "At least one of description, expiresAt, guardrails must be provided"
}
----

`403 Forbidden`::
Returned if the user does not have 1 of the roles listed in <<#patch-privs>>.

`404 Object Not Found`::
Returned if `CREDENTIAL_ID` does not match the ID of an existing credential.

`409 Conflict`::
Returned if you supplied a `payloadVersion` field that no longer matches the credential's current revision.

[#patch-example]
=== Examples

The following example extends the `stocks/massive/api-key` credential's expiration by 6 months, and adds the Analytics Service to its `allowedServices` guardrail, keeping the existing `n1ql` entry and URL whitelist:

[source,bash]
----
curl -u Administrator:password -X PATCH \
     'http://127.0.0.1:8091/settings/credentials/stocks/massive/api-key' \
     -H 'Content-Type: application/json' \
     -d '{
           "expiresAt": 1805068800000,
           "guardrails": {
             "allowedServices": ["n1ql", "cbas"],
             "urlWhitelist": {
               "allAccess": false,
               "allowedUrls": ["https://api.massive.com/"]
             }
           }
         }' | jq
----

[[delete-credential]]
== Delete a Credential

Delete a credential from the credential store.

.Delete a Credential
----
DELETE /settings/credentials/{CREDENTIAL_ID}
----

CAUTION: Couchbase Server does not check whether a credential is currently in use before deleting it — by a grant, a guardrail, or a service such as an external collection.
Deleting a credential that's still referenced elsewhere does not fail or warn you.
Whatever depends on it starts failing on its next access attempt, instead.

=== curl Syntax

[source,bash]
----
curl -u $USER:$PASSWORD -X DELETE \
     'http://{HOST}:{PORT}/settings/credentials/{CREDENTIAL_ID}'
----

.*Path Parameters*
:priv-link: delete-privs
include::partial$user-pw-host-port-params.adoc[]

`CREDENTIAL_ID`::
The `id` of the credential you want to delete.

[[delete-privs]]
=== Required Privileges

You must have at least 1 of the following roles:

* xref:learn:security/roles.adoc#full-admin[Full Admin]
* xref:learn:security/roles.adoc#credential-admin[Credential Admin]
* xref:learn:security/roles.adoc#security-admin[Security Admin]

=== Responses

`200 OK`::
Returned when Couchbase Server deletes the credential.
A successful call does not return any additional content.
Deleting a credential also revokes every user, group, and service's access to it.

`403 Forbidden`::
Returned if the user does not have 1 of the roles listed in <<#delete-privs>>.

`404 Object Not Found`::
Returned if `CREDENTIAL_ID` does not match the ID of an existing credential.

=== Examples

The following example deletes the `stocks/massive/api-key` credential:

[source,bash]
----
curl -u Administrator:password -X DELETE \
     'http://127.0.0.1:8091/settings/credentials/stocks/massive/api-key'
----
