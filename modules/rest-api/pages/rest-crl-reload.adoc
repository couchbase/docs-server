= Reload CRLs on a Node
:description: A node can be made to immediately reload its Certificate Revocation Lists with the REST API.
:page-topic-type: reference
:page-edition: Enterprise Edition

[abstract]
{description}

[#http-method-and-uri]
== HTTP Method and URI

----
POST /node/controller/reloadCrl
----

[#description]
== Description

Makes the node that receives the request re-read its watched directory, re-download every configured URL, and restore the OOTB CA's CRL.
Other nodes are not affected.
The request does not need the cluster's nodes to be able to reach each other, which makes it usable during the recovery procedure in xref:manage:manage-security/manage-certificate-revocation.adoc#recovery[Recovery: Nodes Cannot Communicate Because of Revocation].

[#curl-syntax]
== Curl Syntax

----
curl -X POST http://<host>:8091/node/controller/reloadCrl -u <username>:<password>
----

== Required Privileges

`cluster.admin.security!write` (xref:learn:security/roles.adoc#full-admin[Full Admin], xref:learn:security/roles.adoc#security-admin[Security Admin]).

[#responses]
== Responses

`200` with that node's CRL status, in the same format as one node's entry in xref:rest-api:rest-crl-status.adoc[Get CRL Status].
