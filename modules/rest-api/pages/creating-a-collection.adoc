= Creating and Editing a Collection
:description: pass:q[Collections can be created by means of the REST API.]
:page-topic-type: reference

[abstract]
{description}

== Description

Collections are created by means of the `POST /pools/default/buckets/<bucket_name>_/scopes/_<scope_name>_/collections` HTTP method and URI.
Collections are edited by means of the `PATCH /pools/default/buckets/_<bucket_name>_/scopes/_<scope_name>_/collections/_<collection_name>_` HTTP method and URI.

== HTTP Methods and URIs

----
POST /pools/default/buckets/<bucket_name>/scopes/<scope_name>/collections

PATCH /pools/default/buckets/\
    <bucket_name>/scopes/<scope_name>/collections/<collection_name>
----

== Curl Syntax

The curl syntax is as follows:

----
curl -X POST -u [admin]:[password]
  http://<hostname-or-ip>:8091/pools/default/buckets/\
    <bucket_name>/scopes/<scope_name>/collections
  -d name=<collection-name>
  -d maxTTL=[integer]
  -d history=[ true | false ]

curl -X PATCH -u [admin]:[password]
  http://<hostname-or-ip>:8091/pools/default/buckets/\
    <bucket_name>/scopes/<scope_name>/collections/<collection_name>
  -d history=[ true | false ]
  -d maxTTL=[integer]
----

== Parameters

bucket-name::
Specifies the name of the bucket within which the new collection is to reside.

scope-name::
Provides the name of the scope within which the new collection is to reside.

name::
Specifies the name of the collection to be created: this name cannot subsequently be changed.

maxTTL:: 
Optional parameter is a period of time in seconds or -1. 
It defaults to 0. 
+
When you set `maxTTL` to 0, the collection inherits the `maxTTL` setting of the bucket.
If the bucket has a `maxTTL` setting greater than 0, documents created or mutated in the collection default to expiring after `maxTTL` seconds.
+
When you set `maxTTL` to value greater than zero (but less than its maximum value of 2147483647), it has the following effects:  
+
--
* It sets a default expiration time for documents you create or mutate in the collection. 
* It sets the maximum time in seconds a document can exist before it expires. You can explicitly set a document to expire before this time. Attempting to set a document to expire after this time has Couchbase Server set the document to expire in `maxTTL` seconds.
--
+
When you set `maxTTL` to -1, it overrides the bucket's `maxTTL` setting. By default, when the bucket has a `maxTTL` setting greater than zero, Couchbase Server sets new and mutated documents in the bucket to expire in `maxTTL` seconds. Setting the collection's `maxTTL` to -1 blocks this behavior so that Couchbase Server does not set a default expiration for documents in the collection. 
+
For more information, see xref:learn:data/expiration.adoc[Expiration].

history::
If the value of the optional `history` parameter is:
+
--
* Not explicitly set by the administrator, the parameter inherits the value of the `historyRetentionCollectionDefault` parameter, used in the creating and editing of buckets.
* Explicitly set by the administrator to `true` or `false`, it potentially overrides, for the current collection, the bucket-wide default established by `historyRetentionCollectionDefault`.
--
+
If the value of `history` is `true`, change history is recorded for the collection.
If the value is `false`, change history is _not_ recorded.
+
This parameter is ignored unless the following settings have been made _at bucket level_:
+
* The value of `storageBackend` is `magma`.
* A positive value is established for `historyRetentionSeconds` or `historyRetentionBytes`, or both.

See xref:rest-api:rest-bucket-create.adoc[Creating and Editing Buckets], for information about bucket parameters.
For an overview of change history, see xref:learn:data/change-history.adoc[Change History].

NOTE: `history` and `maxTTL` are the only parameters that you can edit after you create a regular collection.

[#external-collections]
== External Collections

Both the `POST` and `PATCH` endpoints on this page also manage xref:learn:data/external-catalogs-and-collections.adoc[external collections] when you add the `external=1` query parameter.
An external collection points at one table inside an xref:rest-api:external-catalogs-api.adoc[external catalog]'s namespace.
It does not hold any data itself, and every query against it reads directly from the remote Iceberg table's data files.

Creating or altering an external collection only validates the syntax of the parameters you supply.
Couchbase Server does not contact the catalog or storage backend until a query actually runs against the collection.
A typo in `tableName` or `namespace` does not surface until you run a query, not at creation time.

This feature requires the credential store, which is available only in Enterprise Edition.
Community Edition cannot create or query external collections.

NOTE: External collections do not appear under their scope in the Web Console's bucket, scope, and collection navigation view.
You can still manage and query them through {sqlpp} or the REST API.

[#external-collections-parameters]
=== Parameters

An external collection accepts a different, larger set of parameters than a regular collection.

`name`::
Required.
The name of the external collection.
You cannot change this after you create it.

`catalogType`::
Required.
Must be `ICEBERG`.
This is the only supported value.

`catalog`::
Required.
The name of the xref:rest-api:external-catalogs-api.adoc[external catalog] that hosts the table.

`credentialId`::
Required.
References a stored credential used to authenticate to the storage backend where the table's data files live.
This is a different concern from the catalog's own credential, and the two often need different credential types.

`namespace`::
Required.
The Iceberg namespace that contains the table, equivalent to a database or schema in the catalog.

`tableName`::
Required.
The name of the Iceberg table to expose.

`snapshotId`::
Optional.
Pins the collection to a specific Iceberg snapshot ID instead of always resolving the current snapshot.

`snapshotTimestamp`::
Optional.
Pins the collection to the snapshot that was current at a specific timestamp.

`decimal-to-double`::
Optional boolean, defaults to `false`.
Converts Iceberg `decimal` columns to native JSON numbers instead of exact-value strings.
Setting this to `true` trades exactness for a native numeric type.
Leave it at the default when you need exact decimal values.

`parallelScans`::
Optional integer, defaults to `1`.
Controls how many of the table's underlying data files the scanner reads concurrently for one query.
+
This setting only affects parallelism inside the Iceberg scanner itself.
It does not change the Query service's own query-level parallelism, and a query against an external collection always runs as a single scan operator regardless of this value.
+
Raising `parallelScans` can reduce query time for a table with many relevant files, at the cost of more simultaneous connections to storage.
Set it too high for your storage backend's connection limits, and you risk connection resets or throttling instead of a speedup.
+
Pass this parameter as a JSON integer.
A quoted string value is not accepted.

TIP: Couchbase Server never mutates an external collection.
`INSERT`, `UPSERT`, `UPDATE`, `DELETE`, and `MERGE` all fail with error 3510 against an external collection.

[#creating-an-external-collection]
=== Creating an External Collection

Your account needs the `scope_admin` role, the `bucket_full_access` role, or Full Admin to create an external collection this way.

The following example creates an external collection that exposes the `flights` table from `analytics_catalog`:

[source,console]
----
curl -X POST -u $CB_USER:$CB_PASS \
  "http://node1.example.com:8091/pools/default/buckets/travel-sample/scopes/external/collections?external=1" \
  -d name=flights \
  -d catalogType=ICEBERG \
  -d catalog=analytics_catalog \
  -d credentialId=query/external/iceberg-analytics-table \
  -d namespace=analytics_db \
  -d tableName=flights \
  -d parallelScans=4 | jq
----

If successful, the call returns the collection's assigned `uid`:

[source,json]
----
{"uid": 21}
----

[#altering-an-external-collection]
=== Editing an External Collection

You can change any parameter except `name`.
Your account needs the `scope_admin` role, the `bucket_full_access` role, or Full Admin to alter an external collection this way.

The following example switches on `decimal-to-double` for the `flights` external collection:

[source,console]
----
curl -X PATCH -u $CB_USER:$CB_PASS \
  "http://node1.example.com:8091/pools/default/buckets/travel-sample/scopes/external/collections/flights?external=1" \
  -d decimal-to-double=true | jq
----

If successful, the call returns the collection's assigned `uid`:

[source,json]
----
{"uid": "1"}
----

== Responses

Success returns `200 OK`, for each call.
Failure to authenticate gives `401 Unauthorized`.
A malformed URI fails with `404 Object Not Found`.
If the collection-name is improperly specified, a notification such as `"name":"Length must be in range from 1 to 30"` or `"name":"Can only contain characters A-Z, a-z, 0-9 and the following symbols _ - %"` is displayed.
See xref:learn:data/scopes-and-collections.adoc#naming-for-scopes-and-collections[Naming for Scopes and Collections], for an account of naming conventions.

== Examples

The following call creates a collection named `my_collection_in_my_scope`, within an existing scope named `my_scope`. 
It specifies the default expiration for documents in the collection that's equivalent to two years.
It also specifies that no change history should be maintained for the collection.

----
curl -X POST -v -u Administrator:password \
http://10.143.210.101:8091/pools/default/buckets/\
testBucket/scopes/my_scope/collections \
-d name=my_collection_in_my_scope \
-d maxTTL=63113904 \
-d history=false
----

If successful, the call returns a `uid`, such as the following:

----
{"uid":18}
----

The following call modifies the definition of the collection `my_collection_in_my_scope`; specifying that deduplication should not be applied to the change history for the collection:

----
curl -X PATCH http://localhost:8091/pools/default/buckets/testBucket/scopes/my_scope/collections/my_collection_in_my_scope \
-u Administrator:password \
-d history=true
----
