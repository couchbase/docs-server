= Get and Set Revocation Settings
:description: The cluster-wide certificate revocation settings can be retrieved and changed with the REST API.
:page-topic-type: reference
:page-edition: Enterprise Edition

[abstract]
{description}

[#http-methods-and-uris]
== HTTP Methods and URIs

----
GET  /settings/crl
POST /settings/crl
----

[#description]
== Description

`GET` returns the cluster-wide revocation settings.
`POST` changes them.
The body is a JSON object that contains only the settings to change.
Settings you leave out keep their current values, and `policyPerScope` is merged scope by scope.
`urls`, if given, replaces the whole list.
The call returns after the node receiving it has applied the new settings.

The settings are described in xref:manage:manage-security/manage-certificate-revocation.adoc#settings-reference[Settings Reference].

[#curl-syntax]
== Curl Syntax

----
curl -X GET  http://<host>:8091/settings/crl -u <username>:<password>

curl -X POST http://<host>:8091/settings/crl -u <username>:<password> \
  -H 'Content-Type: application/json' \
  -d '{
        "policyPerScope": {"clientAuth": "<policy>", "nodeToNode": "<policy>"},
        "checkIntermediateCerts": <true|false>,
        "directory": "<path>",
        "dirPollIntervalMs": <integer>,
        "urls": ["<url>", ...],
        "urlPollIntervalMs": <integer>
      }'
----

== Required Privileges

* `GET`: `cluster.admin.security!read` (xref:learn:security/roles.adoc#full-admin[Full Admin], xref:learn:security/roles.adoc#security-admin[Security Admin], xref:learn:security/roles.adoc#read-only-admin[Read-Only Admin]).
* `POST`: `cluster.admin.security!write` (Full Admin, Security Admin).

[#responses]
== Responses

[cols="1,3,4"]
|===
| Code | When | Body

| 200
| Success
| The full settings object (as shown in <<example>>)

| 400
| Invalid parameter
| `{"errors": {"<field>": "<message>"}}`, with the messages below

| 400
| `nodeToNode` enabled without an OOTB CA CRL
| `{"error": "Revocation checking of node-to-node traffic requires a revocation list for the cluster's own CA, and this cluster has none: a CA generated by an older version has no cRLSign key usage and cannot issue one.  Regenerate the cluster CA (POST /controller/regenerateCertificate?forceResetCACertificate=true&dropUploadedCertificates=false) and try again."}`

| 503
| Cluster cannot commit the change
| See xref:rest-api:rest-certificate-revocation.adoc#common-behavior[Common Behavior]
|===

Validation messages:

[cols="1,3"]
|===
| Field | Message

| any unknown key
| `Unsupported key`

| `policyPerScope`
| `policyPerScope must be a JSON object`, `unknown scope: <name>`, `unknown mode: <value>`, `policyPerScope entries must be string:string`

| `dirPollIntervalMs`, `urlPollIntervalMs`
| `The value must be in range from 1000 to 86400000 (inclusive)`

| `urls`
| `urls must be a JSON array`, `urls entries must be strings`, `invalid URL: <url>`, `maximum number of URLs is 100`
|===

[#example]
== Example

[source,bash]
----
curl -s -u Administrator:password -X POST http://10.0.0.1:8091/settings/crl \
  -H 'Content-Type: application/json' \
  -d '{"policyPerScope": {"clientAuth": "Require"}, "urls": ["http://pki.example.com/ca.crl"]}'
----

[source,json]
----
{
  "policyPerScope": {"clientAuth": "Require", "nodeToNode": "Disabled"},
  "dirPollIntervalMs": 60000,
  "directory": "/opt/couchbase/var/lib/couchbase/inbox/crls",
  "checkIntermediateCerts": false,
  "urls": ["http://pki.example.com/ca.crl"],
  "urlPollIntervalMs": 3600000
}
----

Client certificates are now refused unless a current CRL from their issuer shows they are not revoked.
Node-to-node checking is unchanged.
