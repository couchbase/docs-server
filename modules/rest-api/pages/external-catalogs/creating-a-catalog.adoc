= Creating a Catalog
:description: pass:q[You can create a catalog using the `/pools/default/externalCatalogs` REST API endpoint.]
:keywords: external catalog, rest api, apache iceberg, catalog provider
:page-edition: Enterprise Edition
:page-topic-type: reference

[abstract]
{description}
An external catalog defines a connection to an external Apache Iceberg catalog provider such as AWS Glue or a Nessie server.
For more information about external catalogs and collections, see xref:learn:data/external-catalogs-and-collections.adoc[].

== Description

Send a `POST` request to `/pools/default/externalCatalogs` to create a catalog.
Creating a catalog only validates the syntax of the parameters you supply.
Couchbase Server does not contact the remote catalog provider until you query an external collection built on it.

== HTTP Method and URI

----
POST /pools/default/externalCatalogs
----

== curl Syntax

[source,bash]
----
curl -X POST http[s]://<host>:<port>/pools/default/externalCatalogs \
  -u <username>:<password> \
  -d name=<catalog-name> \
  -d catalogType=ICEBERG \
  -d catalogSource=<provider> \
  -d credentialId=<credential-id> \
  [-d <provider-specific-parameter>=<value>]
----

== Parameters

`name`::
Required.
The name of the catalog.
You cannot change this after you create the catalog.

`catalogType`::
Required.
Must be `ICEBERG`.
This is the only supported value.

`catalogSource`::
Required.
Identifies the catalog provider.
See <<Catalog Providers and Parameters>> for the accepted values.

`credentialId`::
Required for most catalog providers.
References a stored credential used to authenticate to the catalog provider.
`NESSIE` and `NESSIE_REST` accept an empty string, since these providers do not always need a credential.
`SQL` does not require this parameter at all, but accepts one if you want to store the connection credential separately from `uri`.
See <<Catalog Providers and Parameters>> for which providers require it.
For more information about the credential store, see xref:learn:security/credential-store.adoc[Credential Store].

Additional parameters vary by `catalogSource`.
See <<Catalog Providers and Parameters>> for the full list.

== Required Privileges

Your account needs the xref:learn:security/roles.adoc#external-catalog-admin[External Catalog Admin] role or xref:learn:security/roles.adoc#full-admin[Full Admin].

NOTE: The equivalent `CREATE CATALOG` {sqlpp} statement enforces its own privilege check at the Query service before it calls this endpoint internally.
Consult the {sqlpp} language reference for the DDL-side privilege requirement.

== Responses

200 OK::
Couchbase Server creates the catalog and returns its stored definition.

400 Bad Request::
The request is missing a required parameter, or a parameter's value fails validation.
Couchbase Server returns a JSON object describing the error, including an error code from <<Catalog Error Codes>>.

== Example

The following example creates a catalog that connects to an AWS Glue Iceberg REST endpoint:

[source,bash]
----
curl -X POST -u $CB_USER:$CB_PASS \
  http://node1.example.com:8091/pools/default/externalCatalogs \
  -d name=analytics_catalog \
  -d catalogType=ICEBERG \
  -d catalogSource=AWS_GLUE_REST \
  -d credentialId=query/external/iceberg-analytics-catalog \
  -d uri=https://glue.us-east-1.amazonaws.com/iceberg \
  -d sigv4SigningRegion=us-east-1 | jq
----

If successful, the call returns the new catalog's definition:

[source,json]
----
{
  "name": "analytics_catalog",
  "catalogType": "ICEBERG",
  "catalogSource": "AWS_GLUE_REST",
  "credentialId": "query/external/iceberg-analytics-catalog",
  "uri": "https://glue.us-east-1.amazonaws.com/iceberg",
  "sigv4SigningRegion": "us-east-1",
  "rev": 1
}
----
